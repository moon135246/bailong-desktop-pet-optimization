# Windows 验证记录

日期：2026-11-10（Asia/Shanghai）。版本：`0.5.1-local.4`。本记录为一次本机验证摘要，不包含账号、聊天、额度数值、进程标识或本机路径。

## 首尾帧平滑衔接

对六段待机动画的首尾帧进行了透明通道正确的 200 ms 插值验证：保持不透明及半透明区域的覆盖度，透明背景保持透明，不在中途异常变亮或变淡。固定首尾帧的 60 Hz 采样中，单步平均 RGB 变化约为原直接切换的 14%～17%；该数字用于核对边界过渡，不代表整段动画逐帧的颜色波动。

自然循环集成检查确认等待新首帧后才开始过渡，过渡结束恢复素材帧率计时；拖动立即取消过渡。姿态差异大的轮廓跳过过渡，隐藏时释放过渡帧，菜单开关可即时生效。

## 透明边缘

对 idle、idle2、drag、landing 四段修复动画的全部 336 帧进行了与原素材的解码对照；保留原时长、渲染比例与偏移。修复版清理了原素材部分帧在裙摆、翅膀外的明显残留色块。其余 31 段文件与原安装素材逐字节一致。

`local.4` 在播放阶段覆盖全部动作，不再仅依赖四段替换素材。先以全部 35 段的 175 个原分辨率样本排查，再对全部 4,426 帧在 384×384 下验证：净化本身不修改解码后 RGB，Alpha 只减不增；Alpha 至少 24、连通面积超过 64 像素的主体和独立特效区域保持原覆盖度。合成样例额外核对了单像素斜线连接、透明／实色帧、半透明覆盖及独立特效。

对白色和深色背景下的八段代表样例比较了实际播放管线：原先 1～4 像素的孤立碎点在这些样例中清除，主体和较大的星星、气泡及飘带仍保留。此检查不保证清除原画中每一种瑕疵；净化默认开启，右键菜单可关闭。

384 像素下净化步骤的本机平均耗时约 1.5～2 ms／帧；720 像素单段样本约 6 ms／帧，均不包含解码和显示时间。不同设备及动作可能有差异。使用既有 Pillow，不增加运行依赖，仍按有限帧流式处理。另已核对开关持久化、快速切换、旧缓存隔离、全部动作首帧与原有首尾过渡。

## 内存采样

优化前同机原版 RSS 样本约 2.4～2.7 GB。`local.1` 优化程序的一次短时采样，桌宠、透明解码器和启动监听合计 RSS 平均约 222.1 MiB，峰值约 232.8 MiB；`local.2` 进行了上述素材修复和打包回归。

RSS 汇总可能重复计入跨进程共享页，不包含 Codex 及其工具进程。采样时使用均衡档位；分辨率、显示缩放、动作、运行时间及设备都会影响结果，不据此承诺所有电脑的具体降幅。

## 上游已有测试差异

同时对上游 `opt.23` 基线和本分支运行了同一组 35 项继承测试，失败集合相同：三项动画时钟用例未等待异步首帧就推进时间，另外几项在 Windows 下以 POSIX 字符串模拟 macOS／跨平台路径，产生路径分隔符或查找差异。

本分支另行进行了等待异步首帧的动作结束／恢复检查、当前 Windows 的真实只读额度连接以及打包自检。没有把继承测试描述为全部通过；本机验证脚本和临时产物不随 Git 仓库上传。

## 范围

当前仅有 Windows x64 实机记录。macOS、Linux 与其他设备未在本分支验收。默认构建使用上游公开素材 Release；素材与运行库来源见 [ASSETS.md](../ASSETS.md)。
